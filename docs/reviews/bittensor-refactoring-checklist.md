## Как отмечаем

Файловый чекбокс закрываем после чтения файла целиком и нужных потребителей, обработки конкретных замечаний, соответствующих проверок и ревью блока. Если менять ничего не нужно, фиксируем это в результате блока; искусственный рефакторинг не требуется. Для удалённого файла читаем исходную версию и проверяем оставшихся потребителей. Для ресурсов, бинарных и сгенерированных данных применяем проверку по их назначению.

Сначала проверяем корректность, затем состояние/жизненный цикл, архитектуру/переиспользование и читаемость — по [workflow](../engineering/workflow.md). На кодовых блоках исполнитель — worker (Sol High), механические подзадачи — helper (Luna High), независимый reviewer — code_reviewer (Sol High) либо reviewer (Astra High) по риску. Reviewer должен быть отдельным от автора агентом. Для смешанного блока явно назначаем области ревью, чтобы не оплачивать повторное полное чтение без причины.

Проходим блоки небольшими связанными частями: некоторые категории содержат десятки файлов и не являются одним заданием агенту. На каждую часть фиксируем исходный снимок, изменённые пути и проверки. Начинаем с B01 и модели данных B02/B03; финансовые операции проверяем вместе с их источниками и UI, даже если они находятся в разных блоках. Ресурсы и тесты читаем рядом с соответствующим сценарием. Обязательные инструкции читаем по маршрутам из AGENTS.md.

При новых правках список исходного снимка не перезаписываем. Новые файлы добавляем в раздел «Изменения после исходного снимка». При переименовании сохраняем исходный пункт и указываем новый путь. Если уже проверенный файл меняется, его пункт и затронутые этапы блока открываем снова. Отдельно отмечаем изменения поведения и требуемую проверку человеком.
